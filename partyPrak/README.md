# Праздник в каждый дом

Сайт компании по организации детских праздников: витрина локаций, подбор
свободной даты, бронирование в три шага и панель менеджера.
PHP + MySQL, без фреймворков и сборщиков.

## Запуск на XAMPP

1. Скопируйте папку проекта в `C:\xampp\htdocs\` (например, `htdocs\partyPrak`).
2. В панели XAMPP запустите **Apache** и **MySQL**.
3. Откройте <http://localhost/partyPrak/install.php> — установщик создаст базу
   `partyprak`, все таблицы и зальёт стартовый каталог.
4. Удалите `install.php`, чтобы его нельзя было запустить повторно.
5. Сайт: <http://localhost/partyPrak/>

Параметры подключения лежат в `config.php` (по умолчанию `root` без пароля —
как в стандартной сборке XAMPP). Если у вас другой логин, поправьте там,
либо создайте файл `.env` по образцу `.env.example` (в git не попадает).

## Публикация на GitHub/GitLab

Git хранит и показывает **код**, но не выполняет PHP и не поднимает MySQL.
Запушенный на GitHub проект люди смогут читать (и клонировать), но открыть
работающий сайт по ссылке на сам GitHub не получится — GitHub Pages отдаёт
только статику, `.php` там просто скачается как текст, а не выполнится.

Чтобы кто-то видел **работающий** сайт в реальном времени, нужен настоящий
хостинг с PHP и MySQL (shared-хостинг, VPS, Railway/Render с PHP-образом
и т. п.) — туда код и доставляется, а Git тут годится только как способ
его туда донести или как история изменений.

Пароль админки (`123`) намеренно лежит в `config.php` открытым текстом и
виден в репозитории — это пет-проект для портфолио, а не боевой сервис,
скрывать тут нечего. Если код когда-нибудь окажется на реальном сервере
с настоящими данными — единственное, что стоит сделать перед этим:

- **Выключить отладку** (`APP_DEBUG=0` в `.env`) — иначе текст ошибки PDO
  может показать фрагмент SQL-запроса.
- **Удалить или защитить `install.php`** после первого запуска — он умеет
  создавать таблицы заново.

Параметры БД тоже переопределяются через `.env` (см. `.env.example`) —
это просто показывает разделение конфигурации от кода, а не попытку
что-то спрятать.

## Панель менеджера

Адрес: **`/admin/`** — например <http://localhost/partyPrak/admin/>.
Пароль: **`123`**.

Панель нигде не залинкована с сайта и открывается только по прямому адресу,
плюс закрыта паролем и помечена `noindex, nofollow`.

Что умеет:

| Раздел | Возможности |
| --- | --- |
| Сводка | новые заявки, всего заявок, сумма подтверждённых, активные локации |
| Заявки | фильтр по статусу, смена статуса, удаление, состав заказа и контакты |
| Локации | правка названия, региона, адреса, описания, цен, вместимости; скрытие с сайта |
| Зоны | переключение «свободна / занята» — сразу влияет на бронирование |

> **О пароле.** Лежит в `config.php` открытым текстом (`const ADMIN_PASSWORD =
> '123'`) — сознательно, напоказ: это пет-проект для портфолио, скрывать
> пароль незачем. `hash_equals()` в `admin/auth.php` всё равно сравнивает
> его постоянным временем — не ради секретности, а как демонстрация приёма
> защиты от подбора по задержке ответа. Если когда-нибудь понадобится
> настоящий хеш — переход на него занимает две правки: положить в константу
> `password_hash('пароль', PASSWORD_DEFAULT)` и заменить `hash_equals` на
> `password_verify` в `admin_check_password()`.

## Структура

```
config.php          настройки БД, пароль админки, старт сессии
install.php         разовый установщик: база, таблицы, каталог
index.php           главная
search.php          подбор площадки
seat.php            выбор зон
booking.php         оформление + запись заявки в БД
submit-quick.php    приём быстрой заявки из модального окна

includes/
  db.php            PDO-подключение и понятная страница ошибки
  schema.php        DDL таблиц и стартовые данные
  repo.php          все SQL-запросы (в шаблонах SQL нет)
  helpers.php       money(), plural(), format_date(), e() и валидация
  header.php        <head> и шапка сайта
  footer.php        подвал, окно заявки, подключение скриптов

admin/              панель менеджера (auth.php, layout.php, admin.css и страницы)
css/                tokens → base → components → pages
js/                 ui.js (ядро) + скрипт под каждую страницу
images/             фотографии (оптимизированы, см. «Производительность»)
scripts/            разовый скрипт пересжатия картинок
```

## Как считаются деньги

Итоговая сумма **всегда пересчитывается на сервере** из цен в базе
(`booking.php`). То, что пришло из браузера, для расчёта не используется —
подменить цену через инструменты разработчика нельзя. JavaScript считает ту же
сумму только для мгновенного предпросмотра.

Тарифы услуг различаются по полю `unit`:

| unit | расчёт |
| --- | --- |
| `guest` | цена × количество гостей |
| `hour` | цена × минимальное число часов |
| `fixed` | фиксированная сумма за заказ |

## Работа без JavaScript

Сайт остаётся рабочим с отключённым JS: поиск — обычная GET-форма, зоны —
чекбоксы внутри формы, оформление — обычный POST. Скрипты добавляют
предпросмотр суммы, галерею, модальные окна и уведомления.

## Валидация и защита

**Валидация.** Каждое поле проверяется отдельно (`includes/validate.php`), а не
общим списком: имя, телефон (формат + число цифр), email, дата (не в прошлом
и не дальше двух лет), комментарий по длине. Ошибка подсвечивается у
конкретного поля (`booking.php`) — форма не сбрасывается и не показывает
общую надпись «что-то не так».

**От инъекций:**
- SQL — везде подготовленные выражения PDO с плейсхолдерами
  (`ATTR_EMULATE_PREPARES = false`, то есть это настоящий prepare на стороне
  MySQL, а не эмуляция); ни один SQL-запрос не собирается конкатенацией
  строки с пользовательским вводом.
- XSS — весь вывод идёт через `e()` (`htmlspecialchars` с `ENT_QUOTES`);
  единственные места без нее — целые числа, уже проверенные `int_param()`,
  и собственные константы шаблона (иконки, CSS-классы).
- CSRF — токен на **всех** формах, которые пишут в базу: заявка с главной,
  оформление заказа и все формы админки. Токен из чужой вкладки/сайта не
  совпадёт с тем, что лежит в сессии, — запрос отклоняется.
- Заголовки ответа (`includes/security.php`): `X-Content-Type-Options`,
  `X-Frame-Options: DENY` (админку нельзя встроить в чужой `<iframe>` для
  clickjacking), `Referrer-Policy`, а также `Content-Security-Policy` —
  браузер не выполнит скрипт, встроенный в страницу через уязвимость,
  если он не с `'self'`.

**От спама и перебора:**
- Honeypot-поле в обеих публичных формах — не видно человеку, но простые
  боты заполняют все поля подряд; заполненное значение отбрасывает заявку
  молча, без подсказки боту.
- Троттлинг отправок по сессии (не чаще раза в 10 секунд) — не даёт
  зафлудить форму скриптом.
- Вход в админку блокируется на минуту после 5 неверных паролей подряд,
  сравнение — через `hash_equals` (постоянное время, нельзя подобрать
  пароль по задержке ответа).
- При входе меняется идентификатор сессии (защита от session fixation),
  сессия админки истекает после 30 минут бездействия.

## Дизайн-система

Настроение — карамель, конфетти и вечерний фейерверк. Значения объявлены один
раз в `css/tokens.css`, компоненты обращаются только к переменным.

| Роль | Токен | Значение |
| --- | --- | --- |
| Ведущий акцент | `--pink` | `#ff3d7f` |
| Тёплый акцент | `--amber` | `#ffb627` |
| Прохладный акцент | `--mint` | `#12cdbe` |
| Тёмная основа | `--berry` | `#2b0a45` |
| Бумага | `--paper` | `#fffaf3` |

Варианты `*-deep` — только для **текста** на светлой подложке: фирменные яркие
оттенки в роли текста давали контраст 2.4–3.0∶1 и выглядели выцветшими.
Текущие значения проверены измерением и проходят WCAG AA (≥ 4.5∶1).

Градиентов два с разными контрактами: `--grad-party` — яркий, под **тёмный**
текст (бейджи), `--grad-cta` — глубже, под **белый** текст главной кнопки.

Порядок слоёв каскада задан явно, поэтому специфичность не влияет на приоритет
и `!important` не нужен:

```css
@layer tokens, base, layout, components, pages, utilities;
```

## Анимации

- Переходы между страницами — View Transitions API (`@view-transition`);
  в браузерах без поддержки переход просто мгновенный.
- Появление шапки, первого экрана и панели поиска — лесенкой.
- Появление блоков при скролле — `IntersectionObserver`.
- Отклик на действия: выбор зоны, подсветка изменившейся суммы, включение
  услуги, раскрытие миниатюр, конфетти после успешной брони.
- Изображения проявляются в момент фактической загрузки.
- Всё гасится при `prefers-reduced-motion: reduce`.

## Производительность

- Шрифты грузятся асинхронно (`media="print"` + `onload`) — страница не ждёт
  стороннего сервера перед первой отрисовкой. Запрошены только используемые
  начертания.
- Изображения пересжаты под реальный размер показа: контент выше сгиба весит
  ~110 КБ вместо ~370 КБ, весь используемый набор — 4.15 МБ вместо 8.5 МБ.
  Скрипт `scripts/optimize_images.py` запускается вручную, трогает только
  подключённые файлы и никогда не увеличивает их.
- Замер на статической версии: локальные ресурсы готовы за ~200 мс,
  `load` — до ~650 мс на холодном кэше и 30–40 мс на повторном заходе.

## Доступность

- Семантическая разметка, прайс — настоящая `table`, отзывы — `figure`/`blockquote`.
- Ссылка «Перейти к содержимому».
- Модальные окна и лайтбокс: ловушка фокуса, `Escape`, возврат фокуса, `aria-modal`.
- Зоны и услуги — настоящие чекбоксы, доступные с клавиатуры.
- Уведомления выводятся в регион с `aria-live`.
- Весь декор помечен `aria-hidden`.
- Блоки прячутся до появления только при работающем JS (класс `js` на `<html>`).

## Ограничения

Оплата не подключена: после подтверждения заявка сохраняется в базу со статусом
«Новая» и показывается экран подтверждения. Письма не отправляются.
Данные каталога демонстрационные.
